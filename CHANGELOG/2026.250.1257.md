# 2026.250.1257 — vnc: add the session method (Cutover E E-1)

## Summary

Adds the `session` method to the `vnc` verb (plan `nested-capture-architecture.md`, Cutover E, unit 1): the host-side detached RFB framebuffer recorder — the VNC analogue of plugin-spice's session (Cutover A). It is implemented over the runner's GENERIC background-session service (plugin-check's compiled-in `verb:session` seam); NO core changes — the genericity proof for a second capture plugin.

- **schema/vnc.cue** — `session` joined the `method` enum; new per-verb modifiers `action`/`fps`/`session_id`/`state_dir`/`artifact_dir`/`log_dir`/`venue`/`phase` (mirroring `#SpiceInput`); `params/cue_types_gen.go` regenerated by the documented `cue exp gengotypes` pipeline (package `params` + `@go(params)` wrapper + the schemagen yaml-retag transform — byte-identical regeneration proven on the pre-change schema).
- **session_method.go** — the provider-side dispatch: runSession (`start|stop|status`), buildSessionSpawn (this plugin's own binary in recorder mode + the `CHARLY_VNC_*` env), and submission over the EXISTING InvokeProvider reverse leg — class `verb`, word `session`, `ops.OpExecute` — the same E3b channel the graphics endpoint resolution rides. The provider spawns no process and knows no transport. Plan-step sessions fall back to `session_id: "default"` + a provider-owned temp state dir (spice's record_name chain has no analogue: vnc has no record method).
- **recorder.go** — the detached recorder engine: dials the host-pre-resolved RFB endpoint, polls FULL non-incremental framebuffer updates at fps (default 5, 100 cap) into `<state_dir>/frames.mjpeg`, and on SIGTERM/SIGINT finalizes the deterministic `FINAL` marker + the shared `#EvidenceRow` `row.json` (`instrument`/`origin`/`verb`/`artifact`).
- **cmd/serve** — hidden recorder mode (`CHARLY_VNC_RECORDER=1`) on the existing binary.
- **provider.go** — `session` dispatched before dialing (the recorder owns the wire); `vncEnv` gains `venue` for evidence-row provenance.
- **ADE plan** — `charly.yml` gains three ordered lifecycle checks (`vnc-session-start` → `vnc-session-status` → `vnc-session-stop`) exercising the method against a live wayvnc endpoint.
- **go.mod** — sdk `v0.2026234.347` → `v0.2026248.1237`, spec `v0.2026232.520` → `v0.2026248.1234` (the session seam's `CheckContext.InvokeProvider` contract; same pair plugin-spice consumes).

A NEW test fixture proves the changed runtime path over a real wire: `rfb_server_test.go` — a minimal RFC 6143 RFB server stub (handshake incl. None security + Raw framebuffer updates), and `TestRunSessionRecorderAgainstRealRfbServer` runs the recorder end to end against it (dial → framebuffer polling → finalize).
